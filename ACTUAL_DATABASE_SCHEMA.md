# Actual Database Schema Documentation

This document provides the **actual** database schema as implemented in the codebase, correcting any discrepancies with the original ER diagram.

## 🗄️ Firestore Collections

### 1. **users** Collection
```typescript
interface User {
  id: string;                    // Auto-generated by Firestore
  displayName: string;           // User's full name
  email: string;                 // User's email (unique)
  isAdmin: boolean;              // Admin status (based on email whitelist)
  createdAt: Timestamp;          // Account creation date
  updatedAt?: Timestamp;         // Last profile update
}

// Example document:
{
  "displayName": "John Doe",
  "email": "john@example.com",
  "isAdmin": false,
  "createdAt": "2025-01-15T10:30:00Z"
}
```

### 3. **orders** Collection
```typescript
interface Order {
  id: string;                    // Auto-generated by Firestore
  userId: string;                // Reference to user who placed order
  items: OrderItem[];            // Embedded array of order items
  customerInfo: CustomerInfo;    // Billing and shipping information
  totalAmount: number;           // Total order amount
  paymentMethod: 'bkash' | 'nagad' | 'cash'; // Payment method
  status: 'pending' | 'paid' | 'shipped' | 'delivered' | 'cancelled';
  transactionId?: string;        // Payment gateway transaction ID
  createdAt: Timestamp;          // Order creation date
  paidAt?: Timestamp;            // Payment completion date
  shippedAt?: Timestamp;         // Shipping date
  deliveredAt?: Timestamp;       // Delivery date
```

## 🔗 Relationships and References

### Foreign Key Relationships:
- `orders.userId` → `users.id`
- `products.category` → `categories.slug` 
- `orderItems.productId` → `products.id` (embedded in orders)

### localStorage References:
- `cart` → references `products.id`
- `wishlist_{userId}` → contains full product objects
- Both are synced when products are updated

## 🏗️ Data Access Patterns

### Common Queries:
```javascript
// Get user's orders
query(collection(db, 'orders'), where('userId', '==', userId))

// Get products by category  
query(collection(db, 'products'), where('category', '==', categorySlug))

// Get featured products
query(collection(db, 'products'), where('featured', '==', true))

// Get active carousel slides
query(collection(db, 'carouselSlides'), where('isActive', '==', true))
```

### Security Rules Applied:
- Users can only read their own orders
- Products and categories are publicly readable
- Only admins can create/update/delete products, categories, and carousel slides
- Users collection is readable by authenticated users, writable by owners
